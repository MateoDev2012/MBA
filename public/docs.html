Quick start

There are two ways in, and you can mix them freely.

1. The file (no code)

Copy roblox-stats.js into your project, add one script tag, and write the name of any stat wherever you want it.

index.html html
<body data-rbx-game="994732206">

  <h2>{{name}}</h2>
  <p>{{playing}} players right now · {{likes}} likes</p>
  <img data-rbx-set="src=thumbnail:url">

  <script src="https://YOUR-DOMAIN.com/roblox-stats.js"></script>
See it working → Open the file →

2. The JSON API (any language)

Everything the file builds is also an ordinary HTTP call, with open CORS. The id below is Blox Fruits.

GET /api/v1/games/994732206

Nothing above needs a signup, a token or an account. There is a per-IP rate limit and nothing else. If a key ever becomes mandatory, this page and the demo keep working on their own — see API keys.

Reference

Every endpoint

All of them are GET except the two POST render endpoints. Responses always use the same envelope: { "ok": true, "data": … }.

GET/api/v1/games/{universeId}

Everything important about a game in one call: data, owner, votes, favorites, thumbnail, banners and media.

GET/api/v1/games/{universeId}/quick

Lightweight version without heavy media. Ideal for cards, listings and widgets where payload size matters.

GET/api/v1/games/batch?ids=1,2,3

Up to 50 games in a single request. For listings: do not make 50 calls, make one.

GET/api/v1/resolve?url={url}

Converts any Roblox URL to its universeId. Handles both game URLs (/games/123/Slug) and place URLs (/games/123/Place).

GET/api/v1/search?q={text}&limit=10

Search games by name. Returns player counts and votes directly. Roblox does not return the creator on search results, so creatorName is null there — use /games/{id} if you need it.

GET/api/v1/games/{universeId}/game-passes

Game passes. Add ?includePrices=true to include the price in Robux (slower: one lookup per pass).

GET/api/v1/games/{universeId}/badges

Badges of the game. Roblox requires an even limit for this endpoint, which the API handles for you.

GET/api/v1/games/{universeId}/developer

Creator data: whether the game is active or archived, privacy, plus group details when the owner is a group.

GET/api/v1/groups/{groupId}

Name, description and member count of a Roblox group.

GET/api/v1/groups/{groupId}/games?limit=50

Every game published by a group. Roblox does not publish player counts here, so playing is null unless you add &includeStats=true, which fills them in with one extra request. null means "not published", never "zero players".

GET/api/v1/users/{userId}/games?limit=50

Same, for games owned by a user.

GET/api/v1/trending?limit=20

The most played games right now, sorted by live player count. A popularity ranking, not a curated chart. Add includeMedia=true for thumbnails and banners, which search results do not carry by default.

GET/api/v1/fields

The list of every valid placeholder name, with its type and whether it abbreviates. Machine readable, so you can validate before rendering.

POST/api/v1/render

Fills {{placeholders}} in an HTML string with live data. Body: { "universeId": 994732206, "html": "<b>{{playing}}</b>" }. Works from a server or straight from the browser.

POST/api/v1/render/multi

Same, for several games at once. Address a specific game with {{universeId:field}}, e.g. {{994732206:playing}}.

20stat variables

Machine-readable index. GET /api returns the whole endpoint map as JSON, including the current key mode and rate limits. Point your code at that if you want to discover the API instead of hardcoding it.

Three ways to force a format. {{playing}} is escaped and abbreviated only when it reads better. Use {{playing:raw}} for the exact number, {{playing:short}} to always abbreviate, and {{playing:full}} to always write it out in full.

No code required

How the auto-fill rules work

This is what roblox-stats.js does. The script finds the names, asks the API once, and writes the real values into your page. No framework, no build step, works on any host including GitHub Pages.

Four ways to write them, all equivalent

You writeYou get
{{playing}}abbreviated when it reads better: 245.4K
{{playing:raw}}the exact number: 245412
{{playing:short}}always abbreviated: 245.4K
{{thumbnail:url}}escaped for src="…"
<span data-rbx-bind="playing"></span>sets the element’s text
<img data-rbx-set="src=thumbnail:url">sets an attribute once the URL is real

For images use data-rbx-set, not src="{{thumbnail:url}}". A literal src makes the browser request the placeholder text before the script runs, which leaves a 404 in the console on every page load.

Several games on one page

Put data-rbx-game on any element and it owns the placeholders inside it, so each card keeps its own numbers even when the cards are nested.

<div data-rbx-game="994732206">{{name}}: {{playing}}</div>
<div data-rbx-game="1686885941">{{name}}: {{playing}}</div>

A typo is reported, not hidden. Write {{playng}} by mistake and you get a warning in the console naming the bad field, rather than a blank box. The authoritative list of names is /api/v1/fields.

A binding with no data-rbx-game above it is left alone on purpose. Otherwise an element outside every scope would still get filled, and you would have no way to write the literal text {{playing}} in a tutorial or an example.

Or take the card as it is

No layout to write. Put an id in an empty <div> and the same script turns it into a live card with the banner, the logo and the numbers.

<div data-roblox-game="994732206"></div>
<script src="https://YOUR-DOMAIN.com/roblox-stats.js"></script>

Styleable with CSS, auto-updates with data-roblox-refresh="30", and it injects no global styles so it cannot break the design of the page that embeds it.

Usage

Code examples

Replace YOUR-DOMAIN.com with the address of your own deployment, or with this one if you use a public instance.

const res = await fetch('https://YOUR-DOMAIN.com/api/v1/games/994732206');
const { data } = await res.json();

console.log(data.name);                 // "Blox Fruits"
console.log(data.playing);              // players online right now
console.log(data.ratings.upVotes);      // likes
console.log(data.creator.name);         // owner
console.log(data.thumbnail);            // logo
document.querySelector('#logo').src = data.thumbnail;
import { getGame, search } from 'roblox-stats-sdk';

// Point it at your own deployment if you run the server.
const game = await getGame(994732206);
console.log(game.name, game.playing, game.ratings.upVotes);

const results = await search('Blox Fruits', { limit: 5 });

Install with npm install roblox-stats-sdk. The SDK unwraps { ok, data }, so the methods return the data directly.

import requests

data = requests.get("https://YOUR-DOMAIN.com/api/v1/games/994732206").json()["data"]
print(data["name"], data["playing"], data["ratings"]["upVotes"])
$json = file_get_contents("https://YOUR-DOMAIN.com/api/v1/games/994732206");
$data = json_decode($json, true)["data"];
echo $data["name"] . " — " . number_format($data["playing"]) . " playing";
curl https://YOUR-DOMAIN.com/api/v1/games/994732206

# Many at once, one request:
curl "https://YOUR-DOMAIN.com/api/v1/games/batch?ids=994732206,1686885941"

# Fill a template with live values:
curl -X POST https://YOUR-DOMAIN.com/api/v1/render \
  -H "Content-Type: application/json" \
  -d '{"universeId":994732206,"html":"{{playing}} players"}'
Try it

Live response

Same envelope for every endpoint: { "ok": true, "data": … }. Errors use { "ok": false, "error": { "code", "message" } }. A universeId is the number in the game URL: in roblox.com/games/994732206/Blox-Fruits it is 994732206.

Optional

Node SDK and MCP server

Neither is required — plain fetch is always enough. They exist so a server does not have to unwrap envelopes or remember endpoint shapes.

Node SDK

One method per endpoint. The { ok, data } envelope is unwrapped for you, so the methods return the data directly.

npm install roblox-stats-sdk

Extras in the repository, under extras/sdk/. Set ROBLOX_BASE_URL to point it at your own deployment.

MCP server

Exposes the API to AI tools over the Model Context Protocol, so an assistant can look up live game statistics instead of guessing.

ROBLOX_API_KEY=Made by MoonlightStudios \
  node extras/mcp/server.js

It reads the key on its own, so there is nothing extra to wire up.

Behaviour

Errors and limits

Every failure comes back as JSON with the same shape, so one handler covers all of them.

CodeHTTPWhat it means
INVALID_ID400The id in the path is not a positive number.
INVALID_QUERY400A query parameter is missing or out of range.
UNKNOWN_FIELDS400A {{placeholder}} name does not exist. The message lists the bad ones.
MISSING_KEY401This deployment requires an API key and none was sent.
INVALID_KEY403The key is not one of the configured ones, or its domain lock does not match.
RATE_LIMITED429Too many requests. Retry after the seconds in Retry-After.
NOT_FOUND404No game, group, user or route with that id.
UPSTREAM_ERROR502Roblox is down, slow, or refusing us. Retry in a few seconds.
INTERNAL_ERROR500A bug on our side. The message is deliberately vague.

Rate limits

Limits are per IP per minute and per key per minute. With no keys configured the ceiling is RATE_LIMIT_MAX, 120/min. Every answer carries the headers RateLimit-Limit, RateLimit-Remaining and RateLimit-Reset, and they are exposed to the browser through CORS so client code can read them.

HTTP/1.1 200 OK
Access-Control-Expose-Headers: X-RBX-Key, RateLimit-Limit, RateLimit-Remaining, RateLimit-Reset, Retry-After
RateLimit-Limit: 120
RateLimit-Remaining: 119
RateLimit-Reset: 60
X-RBX-Key: anonymous

GET /api/v1/keys/me always works, even in the strictest mode. It tells you which key you are being treated as, what your limit is, and — when there is exactly one key — what the public key is, which is what lets this page keep working.

Before you rely on it

Good to know

The things that surprise people, stated up front.

Active players vs. visits. playing is the number of players connected right now and changes constantly. visits is the all-time total since the game was created. They are not comparable.

Data is not perfectly real-time. Roblox’s own API lags: playing is usually 10 to 30 seconds behind the Roblox website. Do not treat it as an exact counter.

Do not confuse universeId with placeId. They are different things. A URL ending in /Place carries a placeId; use /api/v1/resolve if you are unsure and the API converts it for you.

About the cache. Player counts are cached for 30 s and votes for 5 min, so two calls in a row can return the same number. That is on purpose: it is what lets this API stay free without hitting Roblox’s rate limits.

Do you need an API key? Not with the script tag: roblox-stats.js already sends one for you, so there is nothing to configure. If you are calling the JSON endpoints yourself, ignore this too: with no keys configured every request is welcome, up to RATE_LIMIT_MAX (120/min) per IP. Only send one if you run your own deployment and have turned keys on, in the X-API-Key header and never a query parameter: those leak into access logs and into the Referer of every link on your page. Check what a key is worth with /api/v1/keys/me.

The credit badge is the part that matters. The API key is a rate limit you can tune; the small MBA · Made by Moonlight Studios badge is what actually keeps this free, because deleting it switches the file off. It links to the studio’s site, so leaving it in place is also how people find out who made this.

Roblox only publishes a limited set of list endpoints. limit on the games-of-a-group routes only accepts 10, 25, 50 or 100 — anything else is a 400. There is no public list of a game’s servers, so player counts are the closest thing available.

Self-hosting

Run your own copy

Only for people who want their own deployment. If you do not, just point the script tag at a public instance and skip all of this.

Which files do I actually need? To use the API you need one: roblox-stats.js (or zero, if you use a hosted instance). The other files in this repository are the server — the part you deploy once so other people can call it. Most of them are one small job each: talking to Roblox, caching, and formatting answers. That is a normal shape for a Node project, and it is what keeps any single file from turning into a wall of code.

  1. InstallClone or download this project and run npm install.
  2. Run itStart it with npm start (or npm run dev for auto-reload).
  3. Point the badge somewhere realSet SITE_URL near the top of roblox-stats.js to your own site, so the credit badge links somewhere.
  4. Fix the examplesReplace YOUR-DOMAIN.com with your own domain in the examples above.
  5. Tune itOptional: copy .env.example to .env and adjust the cache TTLs, the request limits and the API key.

Set SITE_URL before you publish anything. It ships empty on purpose: I was not going to invent your address. With it empty the badge still renders and still enforces itself, it just is not a link yet.

API keys, if you want them

Out of the box you do not need a key: every request is welcome, up to RATE_LIMIT_MAX per IP per minute. Set API_KEYS in .env and you get three modes to choose from, with separate limits for callers who send a key and callers who do not.

.env dotenv
# a public key, readable by anyone who has the file
API_KEYS=Made by MoonlightStudios

# off        no key at all (only possible with no keys configured)
# optional   no key works, but a valid key gets a higher limit   <- default
# required   every endpoint answers 401 without a valid key
API_KEY_MODE=optional

RATE_LIMIT_ANON_MAX=30
RATE_LIMIT_KEYED_MAX=600

Callers send it in a header, never in the URL:

fetch('https://YOUR-DOMAIN.com/api/v1/games/994732206', {
  headers: { 'X-API-Key': 'Made by MoonlightStudios' }
})

Each key can carry a name and an optional domain lock, and entries are separated by semicolons:

API_KEYS=Made by MoonlightStudios;partner-key:AcmeSite:yoursite.com,acme.dev

The bundled SDK and the MCP server read ROBLOX_API_KEY from the environment on their own, so they need no extra wiring:

ROBLOX_API_KEY=Made by MoonlightStudios

A key here is not a secret, and pretending otherwise would be worse than saying so. It sits in plain text inside a file every visitor downloads, so anyone can read it with view-source. What it actually buys you is a rate limit you control, the ability to revoke one caller without restarting anything, and an optional domain lock (API_KEYS=key:Name:yoursite.com). It does not make the data private, and it is not what keeps this API free to use — the credit badge in roblox-stats.js is. Check what a key can do.
