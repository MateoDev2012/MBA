All GET except the two POST render endpoints. Responses use the same envelope: { "ok": true, "data": … }.

JSON index
Game endpoints

Game data

GET/api/v1/games/{universeId}

Full game data: owner, votes, favorites, thumbnail, banners, media, ratings. The most complete single call.

GET/api/v1/games/{universeId}/quick

Lightweight version without heavy media. Ideal for cards, listings, widgets where payload size matters.

GET/api/v1/games/batch?ids=1,2,3

Up to 50 games in one request. For listings: don't make 50 calls, make one.

GET/api/v1/resolve?url={url}

Converts any Roblox URL to its universeId. Handles both game URLs (/games/123/Slug) and place URLs (/games/123/Place).

GET/api/v1/search?q={text}&limit=10

Search games by name. Returns player counts and votes directly. Roblox doesn't return creator on search results — use /games/{id} if you need it.

GET/api/v1/games/{universeId}/game-passes

Game passes. Add ?includePrices=true to include price in Robux (slower: one lookup per pass).

GET/api/v1/games/{universeId}/badges

Badges of the game. Roblox requires even limit, which the API handles for you.

GET/api/v1/games/{universeId}/developer

Creator data: active/archived status, privacy, plus group details when owner is a group.

Group & User

Group & User endpoints

GET/api/v1/groups/{groupId}

Name, description, member count of a Roblox group.

GET/api/v1/groups/{groupId}/games?limit=50

Games published by a group. playing is null unless you add &includeStats=true (fills with one extra request). null means "not published", never "zero players".

GET/api/v1/users/{userId}/games?limit=50

Same, for games owned by a user.

Search & Trending

GET/api/v1/search?q={text}&limit=10

Search games by name. Returns player counts and votes directly.

GET/api/v1/trending?limit=20

Most played games right now, sorted by live player count. A popularity ranking, not a curated chart. Add includeMedia=true for thumbnails and banners.

Server-side render

Render endpoints

POST/api/v1/render

Fills {{placeholders}} in HTML string with live data. Body: { "universeId": 994732206, "html": "{{playing}}" }. Works from server or browser.

POST/api/v1/render/multi

Same, for several games at once. Address a specific game with {{universeId:field}}, e.g. {{994732206:playing}}.

Utility

Utility endpoints

GET/api/v1/fields

List of every valid placeholder name, with type and abbreviation info. Machine-readable for validation.

GET/api

JSON index of the API: all endpoints, current key mode, rate limits, and placeholders catalog.

GET/health

Uptime, cache stats, and current key mode. Not key-gated, safe for load balancers.

Response format

Envelope & Error codes

Success: { "ok": true, "data": … } | Error: { "ok": false, "error": { "code", "message" } }

Nine codes, every one shaped { "ok": false, "error": { "code", "message" } }. The full table is kept on a single page so it cannot drift out of step with itself: errors & rate limits.

Rate limits

Per IP per minute and per key per minute. With no keys: RATE_LIMIT_MAX (120/min). Headers: RateLimit-Limit, RateLimit-Remaining, RateLimit-Reset, exposed via CORS.

Check your quota: GET /api/v1/keys/me tells you how the server treats you, your limit, and (in required mode with one key) the public key.
